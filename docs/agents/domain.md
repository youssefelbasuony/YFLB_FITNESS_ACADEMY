# Domain documentation

Layout: single-context.

- `GLOSSARY.md` is the vocabulary source for product and engineering terms.
- `docs/adr/` contains architecture decision records. Number new records in order and include status, context, decision, and consequences.
- Read the glossary and relevant accepted ADRs before changing data models, APIs, authentication, persistence, or product language.
- Update the glossary when a domain term changes meaning. Add an ADR when a durable architecture choice changes.
- `docs/PROJECT_CONTEXT.md` and `docs/PROJECT_STATE.md` describe current intent and implementation status; inherited Night Gym notes are historical reference.
